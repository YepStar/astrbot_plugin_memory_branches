# 记忆分支 · Memory Branches

AstrBot 4.29.4+ 独立长期记忆插件。借鉴 LivingMemory 的整理、生命周期和图谱思路，重新实现独立空间及检查点，不依赖旧记忆插件运行。对话风格学习也按空间隔离。

## 使用

在 AstrBot 插件页打开“记忆分支”的 dashboard 面板。左侧切换记忆空间；每个来源只能绑定一套空间，QQ 私聊必须独占，创建重复绑定会被拒绝。公共空间可以合并多个明确来源。

- **记忆时间线**：显示总结节点与长期记忆；查看全文，调整重要性和状态。
- **总结最新对话**：从上次成功总结的位置整理到点击时已有的最新完整对话，不要求达到自动总结阈值。后台执行，可刷新查看，重复点击不会创建同空间的并发任务；不同空间可以并行。失败不跳过消息。
- **关联图谱**：记忆与话题、人物、事实及明确关系构成网络；支持缩放、拖动和点选。默认最近 300 条使用中的记忆，浏览器最多渲染 700 个节点，并显示范围。
- **试试看它记得什么**：输入自然聊天问题，查看正式召回使用的片段、命中原因和关键词。不会发消息，不增加访问计数，不生成虚假的“回答”。
- **说话习惯**：20 条新的用户消息后自动学习，或手动学习。每套独立，可整体或逐条关闭。只学习措辞、句式、节奏，不以风格学习更改人格、事实、身份或权限。
- **规则设置**：每套分别配置总结轮数、分段、衰减、保护和归档。默认 10 轮（20 条消息）触发自动总结；跨天或间隔超过 180 分钟分段。公共场景没有固定一问一答时按消息数折算。

空闲分段不等于定时总结。维护器每 30 秒检查触发及生命周期；重要性按实际经过的整天衰减，不会每 30 秒衰减一次。手动总结会分段消费点击时的积压；运行中新来的内容留给下次。私聊尚未收到回复的最后一条用户消息不会单独成为节点。

## 删除与回退

点击总结节点的“删除并回退”，面板先预览将删除多少节点、多少原文及恢复目标。

删除的是**选中的节点及其之后的整个分支**，包括后续总结、待总结原文和对应的 AstrBot 本机会话历史。恢复此前的记忆内容、重要性、访问次数、状态、图谱与说话习惯。其他空间不动。QQ/B站/小黑盒服务器已发出的消息、其他插件的关系值、图片和外部操作不属于本插件的回退范围。

回退期间停止该空间写入；回复进行中时拒绝回退。总结结果带修订号，不能在回退后写回旧内容。跨数据库操作使用持久化恢复日志；中途失败会锁住该空间，重启后继续恢复，不假报成功。若原始 AstrBot 会话被外部手动删掉，需先恢复会话备份，不能凭空重建一个同 ID 的会话。

旧插件没有逐节点完整快照，因此迁入的数据以一个**迁移基线**保存，不伪造历史状态。基线保留迁移时尚未总结的消息；新生成节点之后，删除回退具有完整的快照语义。旧记忆可单独归档，但不能伪装成具有真实历史状态的旧回退节点。

## 记忆规则

重要性内部为 0—1，面板显示 0—10；状态包含使用中、休眠、已归档、被替代、已过期和已遗忘，只有使用中的记忆参与召回。默认每日重要性衰减 1%，满重要性记忆受保护，近期访问次数提供有限保护并逐日回落；低价值旧记忆自动归档，保留可回退数据。

记忆原子保留事实/事件/关系/偏好/计划分类和生命周期：默认分别按 180/7/90/60/2 天处理有效期，过期后再经过 7 天进入遗忘状态。总结近重复默认按 0.92 的词项集合相似度合并，完整快照仍保留合并前版本。

召回在当前空间内融合中文词项、可选向量、图谱关联和重要性排序。向量模型故障会回退到词项和图谱，不丢失总结。归档、休眠、过期等状态不参与正式召回。原始资料和学到的措辞只是参考，不具备系统指令权限。

## 安装及数据

插件目录：`data/plugins/astrbot_plugin_memory_branches`。
数据目录：`data/plugin_data/astrbot_plugin_memory_branches`。
数据文件：`memory_branches.db`，带 SQLite WAL 和事务。

总结模型可配置；留空使用当前会话提供商。向量模型可选，配置后用于新总结及查询；旧记录没有向量时仍支持词项和图谱检索。本次迁移保留 LivingMemory 的全部原向量。

本机迁移使用 `migration.py`，只读源文件；必须先停机或生成一致性备份后迁移。它保留私聊原文、记忆、状态、重要性、原子、图索引原始数据、来源原文以及 Self Learning 共享记录、视频/外部资料和表达习惯。`integrations/bili_shared_memory_backend.py` 是 B站旧接口到新权威库的适配，不会回写旧库。

旧 LivingMemory、Self Learning 的代码和数据保留，停用其记忆接入，避免双写。可从切换前备份恢复原来状态；不要把旧源库和新库同时作为同一来源的权威数据。

## 测试

使用 AstrBot Docker 内置 Python 运行：

```sh
PYTHONPATH=/AstrBot/data/plugins:/AstrBot python -m unittest discover \
  -s /AstrBot/data/plugins/astrbot_plugin_memory_branches/tests -v
```

测试涵盖来源独占、空间隔离、并行总结、失败不推进、近重复回退、风格隔离、主机历史恢复、持久化故障恢复、B站兼容，以及真实 AstrBot/Quart API 链路。

## 源码仓库与当前版本

本仓库发布本机运行的记忆分支适配器 **1.2.2**，不包含聊天原文、记忆数据库、运行配置或凭据。部署当前已迁移的数据时不要再次运行 migration.py。首次迁移脚本的来源映射由本地命令参数显式传入，不在源码中保存账号绑定。

1.2.1 增加按私聊空间设置的 `scene_memory_policy`：默认 `source_based`，显式选择 `immersive_shared_experience` 时，将双方已发生的场景互动按共同经历整理。该口径只适用于独占QQ私聊空间，不跨越其他私聊或公共平台；计划、外部资料与实际工具回执仍保留事实归属。生成、提交与导入入口共同执行清理规则，正文变化时避免保留旧向量。

安装后数据保存在 AstrBot 的 `plugin_data/astrbot_plugin_memory_branches/`，不应提交到源码仓库。迁移与恢复必须整体匹配主会话库、记忆库和陪伴状态，并在停机或一致性快照上操作。

## 1.2.2：账号映射留在本地

初次迁移必须显式提供`--private-route`、`--new-private-route`和所需的`--public-source`映射；已有新版库不要再次执行迁移。公共群聊是否可读由本地记忆空间的来源绑定决定，源码不固定某个群号。升级功能代码保留本地数据库、来源权限和模型配置。
